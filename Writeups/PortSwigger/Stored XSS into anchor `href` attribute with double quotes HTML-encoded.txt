**Objective:** Execute `alert(1)` via Stored XSS, even though the characters `<`, `>`, and `"` are escaped.

**Vulnerability:** Stored XSS within an `href` attribute. The site escapes HTML tags and double quotes but **does not block the `javascript:` protocol**.

**Steps taken:**
1. Opened the post page containing comments.
2. Posted a comment, entering the following into the "Website" field:
javascript:alert(1)

3. Submitted the comment.
4. After the comment was published, clicked on the author's name (which is a link) — the alert triggered.


**Payload:**
javascript:alert(1)


**Why it worked:**
- The site inserts the value from the "Website" field into the `href` attribute of a link.
- The characters `<`, `>`, and `"` are escaped (which is why `<script>` does not work).
- However, the `javascript:` protocol is **not blocked**; it executes JavaScript code when the link is clicked.
- Since this is a Stored XSS vulnerability, the payload is saved on the server and executes for anyone who clicks the link.
